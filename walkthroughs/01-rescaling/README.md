# Same computation, different measured complexity

Open [rescaling.ipynb](rescaling.ipynb). It moves from one hand-calculable ReLU to
the published width-128 checkpoint, reproduces the codec counterexample, and
derives the balancing convention. Prediction prompts precede the computations.
Saved outputs let you read it without starting Jupyter; clear outputs for a fresh
learning pass.

## Run locally

From the repository root, on `walkthrough/rescaling`:

```bash
cd walkthroughs/01-rescaling
uv sync --locked
uv run --locked jupyter lab rescaling.ipynb
```

Select the Python 3 kernel from this environment, then **Restart Kernel and Run
All Cells**. The first cell prints library versions. The notebook needs the full
repository checkout because it reads the existing checkpoint and imports the
original codec. No training, GPU, or external dataset download is needed.

This directory has its own uv project and lock for Jupyter and execution tools.
Python 3.12.14, NumPy 2.3.5 and Matplotlib 3.11.2 match the research environment;
the parent environment and lock are unchanged. Initial setup downloads packages.

To execute without the UI, from this directory:

```bash
uv run --locked jupyter nbconvert --to notebook --execute --inplace \
  --ExecutePreprocessor.timeout=120 rescaling.ipynb
```

The notebook writes PNG/SVG figures, CSV source tables and `provenance.json` under
`outputs/`. These reproducible local exports are ignored by Git; figures and
results are also embedded in the committed notebook. To export a reading copy:

```bash
uv run --locked jupyter nbconvert --to html rescaling.ipynb --output-dir outputs
```

## What is being reproduced

- Source snapshot: `9e56faf915c85a8aefa90f662e46ce94c474ce75`.
- Run: `e1-co-add-w128-i30000-a1`, step 50,000, published under
  `research/coordinator/runs/`.
- Selected rescaling: seed 33200, sigma 0.25, zero-based draw 8, following
  the 16 sigma-0.1 draws in the original sweep.
- Expected code lengths: 95,496 bits before rescaling; 190,728 after; 95,496
  for both balanced copies. All retain 128 units.

The example was selected from an existing exploratory result. It is a
counterexample to invariance of this measurement, not a frequency estimate or a
test of whether gradient descent prefers simple algorithms. The notebook checks
artifact and implementation hashes; it should fail visibly if those inputs
change, rather than silently tell a different story.

## Checks

The committed outputs were generated by executing all cells in order in a fresh
in-process IPython session. All assertions passed. This host blocks Jupyter's
local TCP/IPC sockets, so interactive kernel startup was not verified here.
To reproduce that socket-free check from this directory:

```bash
uv run --locked python check_notebook.py
```

The small driver executes the notebook itself; it contains no duplicate science
code. It updates saved outputs only after every code cell succeeds.

Executable assertions cover the scalar identity, uncompensated and negative-gain
controls, full-domain logit/prediction preservation, unchanged pruning order,
reproduction of the published codec lengths, and balancing equivalence and
idempotence. Fidelity to the source network is kept distinct from task accuracy.
The original `compress()` is called unchanged; this is not an independent codec
implementation audit. The balancing helper deliberately rejects units with a
zero incoming or outgoing norm rather than hiding an undefined ratio.

This teaching branch adds only `walkthroughs/`; scientific training code and
historical results are inherited unchanged from the source snapshot.
